다운로드

① 소스 문서 다운로드

3GPP 스펙(PDF)은 ETSI 서버에서, RFC 문서(TXT)는 IETF rfc-editor.org에서 자동 다운로드. 병렬 다운로드 지원, ETSI _60 버전 자동 탐색.

3GPP / ETSI 경로
$ python scripts/download_etsi_specs.py \
  --spec "24.301,38.331,23.501"
# https://www.etsi.org/deliver/etsi_ts/
# etsi_ts_{series}_{number_10x}/_60/{file}.zip
ETSI ZIP
→
raw/ts_*.pdf
RFC / IETF 경로
$ python scripts/download_rfc.py \
  --rfc 3261 --rfc 8446
# https://www.rfc-editor.org/rfc/rfc{N}.txt
# 89개 Priority RFC 목록 내장
IETF TXT
→
data/rfcs/rfc*.txt
현재 raw/ : 105 PDF + ~95 RFC TXT (data/rfcs/)
2
추출

② 구조 추출 (PDF/TXT → JSONL)

원문서에서 TOC, 섹션 번호, 제목, 본문 텍스트를 파싱. PDF는 PyMuPDF로 페이지별 텍스트 추출 후 regex로 섹션 경계 인식. RFC TXT는 들여쓰기 패턴으로 파싱.

3GPP PDF 추출
$ python scripts/extract_pdf_structure.py \
  raw/ts_124301v18.9.0.pdf
# PyMuPDF로 페이지 텍스트 추출
# TOC 항목 감지 (레벨·페이지·번호)
# → {spec_id}_structure.jsonl
출력 레코드 타입:
spec_meta toc_entry page_text extraction_warning
RFC TXT 추출
$ python scripts/extract_rfc_structure.py \
  --rfc 3261 --rfc 8446
# Regex: ^(\d+(?:\.\d+)*)\.?\s+(.+)$
# TOC 라인 vs body 섹션 구분
# → rfc_{N}_sections.jsonl
별도 파이프라인:
$ ./scripts/run_rfc_pipeline.sh --rfc 3261
# download → extract → load (원커맨드)
3
섹션 경계

③ 섹션 경계 재조정 (build_section_spans.py)

PDF 추출 결과(_structure.jsonl)를 읽어 TOC 위치와 실제 페이지 텍스트를 결합. page_start/page_end를 계산하고, 계층 부모-자식 관계(parent_section)를 확정하여 최종 sections.jsonl 생성.

$ python scripts/build_section_spans.py ts_24_301
# 또는 --all 플래그로 전체 처리
*_structure.jsonl
→
build_section_spans.py
→
{spec_id}_sections.jsonl
출력 필드: section_id · spec_id · section_number · section_title · page_start · page_end · depth · parent_section · content · content_length · brief

DB 빌드

④ SQLite Corpus 빌드 (build_corpus.js)

모든 *_sections.jsonl을 읽어 SQLite DB에 인서트. FTS5 content-sync trigger 자동 적용으로 full-text search 인덱스 동기화. sqlite-vec 확장이 있으면 vector 테이블도 초기화.

$ node scripts/build_corpus.js

# --spec ts_24_301: 특정 스펙만 재인서트

MCP 서버

⑤ MCP 서버 구동 (src/index.js)

Node.js stdio transport로 JSON-RPC 2.0 서버 구동. DB 경로 자동 탐색 후 better-sqlite3 싱글턴 커넥션 생성. 7개 툴 레지스트리에 등록 후 LLM 클라이언트 요청 수신 대기.

MCP 툴 — LLM 설계 철학
설계 철학: LLM이 일반 검색/조회 툴만으로 자율 탐색할 수 있어야 한다. getEmmCause처럼 특정 기능을 하드코딩한 좁은 툴은 제거. LLM이 search_3gpp_docs("EMM cause 18")로 직접 탐색.
Explore (탐색 시작)
Retrieve (내용 조회)
Search (검색)
Meta (운영)
get_spec_catalog
모든 스펙 카탈로그 반환. spec ID, 제목, 버전, 섹션 수 포함. 탐색의 출발점.
filter: string family: string
get_spec_toc
특정 스펙의 목차(섹션 계층) 반환. 섹션 번호·제목·페이지·brief 포함. catalog 다음 단계.
specId * maxDepth sectionPrefix includeBriefs
get_section
섹션 ID 또는 spec+번호로 전문 조회. TOC 탐색 후 확정적으로 내용을 가져올 때 사용.
sectionId specId sectionNumber includeNeighbors maxChars
search_3gpp_docs
키워드 + 시맨틱 하이브리드 검색. BM25 FTS5 + 벡터 코사인 융합. 인용구, Boolean, spec 필터 지원.
query * spec maxResults mode: auto|keyword|semantic|hybrid page
search_related_sections
앵커 섹션에서 부모·자식·형제·의미적 유사 섹션 탐색. get_section 이후 연관 탐색에 활용.
sectionId specId sectionNumber sameSpecOnly maxResults
list_specs
스펙 목록 + 섹션 수. get_spec_catalog의 레거시 호환 버전.
없음
get_ingest_guide
corpus 확장 단계별 가이드. ETSI/RFC 다운로드 URL 패턴, AutoRAG 파이프라인 실행 방법 안내.
type: etsi|rfc|autorag|all *

출력: normalizedText, specFilter, mode, k

FTS5 BM25
→

sections_fts MATCH query — SQLite FTS5 BM25 랭킹. content + section_title 동시 검색.

반환: section_id, keyword_score, snippet

semantic
sqlite-vec
→

쿼리 임베딩 → vec_sections에서 코사인 유사도 검색. 현재 generate_embeddings.js 미실행으로 비활성.

활성화 시: isVectorSearchAvailable() → true

fusion
hybridRanker
→

Reciprocal Rank Fusion 스코어링:

score = α × keyword_score + (1-α) × semantic_score

기본 α = 0.4 (시맨틱 우선). 벡터 비활성 시 actualMode = "keyword"로 폴백.

출력
results[]
→

최대 maxResults개 반환. 각 결과: section_id, spec_id, section_title, content_snippet, score, evidence

LLM은 이 section_id로 get_section을 호출해 전문 취득.

모드별 동작 매트릭스
Mode FTS5 BM25 sqlite-vec 현재 상태 비고
auto ✅ if available keyword (vec 없음) 기본값 — 자동 판단
keyword ✅ ❌ 정상 작동 FTS5 BM25만 사용
semantic ❌ ✅ → keyword 폴백 vec 데이터 필요
hybrid ✅ ✅ → keyword 폴백 generate_embeddings.js 실행 후 활성화
